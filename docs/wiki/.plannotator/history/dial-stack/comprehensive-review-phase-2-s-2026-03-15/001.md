# Comprehensive Review: Phase 2 — Security & Performance

## Context

Phase 1 (Quality & Architecture) is complete in `.full-review/quality-architecture.md`. It found 28 code quality issues and 16 architecture issues. The review is now at Phase 2: Security & Performance.

This project follows **Spec-Driven Development** (`docs/SPEC_DRIVEN_DEVELOPMENT.md`). The review findings will feed directly into requirement IDs and spec modules when remediation begins. No code changes are proposed here — this is the analysis phase only.

## What I Found

### Security — 20 findings

**Critical (4):**
- `postgres_raw_query` exposes unrestricted SQL via `client.unsafe()` — no allowlist, no read-only enforcement
- TS MCP Server port 8081 exposed to host without auth — DIAL Core handles JWT on port 8080, but 8081/8082 bypass it entirely in the current `docker-compose.yml` port mappings
- Workflow config writable by any caller — can silently disable all HAP/PII screening
- `postgres_write_record` accepts any table name including auth/audit tables

**High (6):**
- Hardcoded secrets in `docker-compose.yml` (NEXTAUTH_SECRET, DIAL_API_KEY, InfluxDB tokens)
- PII returned in redaction tool response (defeats the purpose of redaction in audit logs)
- fasttext model downloaded without hash verification (MITM risk, air-gap failure)
- DuckDB hashes file PATH not content (forensic integrity failure — chain of custody broken)
- Python singletons not thread-safe (non-deterministic for legal evidence processing)
- Review approve/reject accepts unverified reviewer identity string

**Medium (7):** Ollama violating Rule 3, Redis exposed without auth, path traversal on parsers, Keycloak HTTP-only, no input size limits, error messages leak schema info, InfluxDB token duplication

**Low (3):** No rate limiting, js-mcp-server blocking core startup, plaintext tokens in Docker network

### Performance — 7 findings

**Critical (1):** Parser output dumps unbounded JSON into single MCP message (OOM / context overflow — no pagination)

**High (3):** HAP model batches all sentences in one pass (OOM on CPU), duplicate PostgreSQL connection pools, Facebook parser loads entire file into memory

**Medium (3):** Language ID blocks on 131MB download, new MCP Server instance per request, O(n²) string concatenation in workflows

### Auth Architecture Note

DIAL Core (port 8080) handles JWT auth via Keycloak — this is the **intended** auth path. The MCP servers are meant to sit behind DIAL. However, `docker-compose.yml` exposes ports 8081 and 8082 directly to the host, creating a bypass. The report will document this as a deployment config issue, not an architecture flaw — the fix is to either remove direct port exposure or add auth middleware as defense-in-depth.
