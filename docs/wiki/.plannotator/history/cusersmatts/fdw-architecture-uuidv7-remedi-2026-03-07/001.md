
# FDW Architecture + UUIDv7 Remediation Plan (Corrected)

## Architecture Decision: FDWs Only (No Apache AGE)

**Decision**: Use Foreign Data Wrappers + Neo4j only. NO Apache AGE.

**Why:**
1. Neo4j already exists as Tier 3 with Semantica
2. `neo4j_fdw` lets PostgreSQL query Neo4j directly
3. No need for hybrid graph engines — keep graph data in Neo4j
4. Simpler architecture — one graph engine, not two

---

## PostgreSQL as Forensic Hub

PostgreSQL becomes the **federated query engine** for all 5 tiers:

```
┌─────────────────────────────────────────────────────────────────┐
│ POSTGRESQL (FORENSIC HUB)                                       │

│ STORAGE FDWs:                                                   │
```

### 1b. Update 01-schema.sql

Configure FDWs and create evidence_master_index in PostgreSQL:

```sql
-- =============================================================================
-- FDW EXTENSIONS
-- =============================================================================

CREATE EXTENSION IF NOT EXISTS duckdb_fdw;
CREATE EXTENSION IF NOT EXISTS neo4j_fdw;
CREATE EXTENSION IF NOT EXISTS parquet_fdw;
CREATE EXTENSION IF NOT EXISTS digest;
CREATE EXTENSION IF NOT EXISTS temporal_tables;

-- =============================================================================
-- DUCKDB FDW SERVER (Tier 1)
-- =============================================================================

CREATE SERVER duckdb_forensic_vault
FOREIGN DATA WRAPPER duckdb_fdw
OPTIONS (database '/data/duckdb/forensic_vault.db');

CREATE FOREIGN SCHEMA duckdb_tier1
FROM SERVER duckdb_forensic_vault
INTO public;

-- =============================================================================
-- NEO4J FDW SERVER (Tier 3)
-- =============================================================================

CREATE SERVER neo4j_knowledge_graph
FOREIGN DATA WRAPPER neo4j_fdw
OPTIONS (
    host 'neo4j',
    port '7687',
    database 'neo4j'
);

CREATE USER MAPPING FOR evidence
SERVER neo4j_knowledge_graph
OPTIONS (username 'neo4j', password 'your_password');

-- =============================================================================
-- PARQUET FDW FOR LANCEDB (Tier 2)
-- =============================================================================

-- LanceDB stores embeddings in Parquet format
-- Configure per-table as needed

-- =============================================================================
-- EVIDENCE MASTER INDEX (PostgreSQL, not MySQL)
-- =============================================================================

CREATE TABLE evidence_master_index (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v7(),
    source_hash DIGEST NOT NULL,  -- SHA-256 (32 bytes, not 64 chars)
    evidence_id UUID NOT NULL,     -- UUIDv7 from DuckDB ingestion_log
    original_filename VARCHAR(1024) NOT NULL,
    tier VARCHAR(16) NOT NULL,     -- 'duckdb'|'lancedb'|'neo4j'|'postgres'|'mysql'
    storage_path TEXT,             -- Where it lives
    creation_timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_accessed TIMESTAMPTZ,
    
    -- Temporal table for chain of custody
    sys_period TSTZRANGE NOT NULL DEFAULT TSTZRANGE(NOW(), NULL)
);

-- Enable temporal tables (automatic history tracking)
SELECT create_temporal_table('evidence_master_index');

-- Indexes
CREATE UNIQUE INDEX idx_evidence_master_hash ON evidence_master_index (source_hash);
CREATE INDEX idx_evidence_master_evidence_id ON evidence_master_index (evidence_id);
CREATE INDEX idx_evidence_master_tier ON evidence_master_index (tier);

-- =============================================================================
-- FOREIGN KEY TO DUCKDB (via FDW)
-- =============================================================================

-- DuckDB ingestion_log is the source of truth for evidence_id
-- PostgreSQL can query it directly via duckdb_fdw:
-- SELECT * FROM duckdb_tier1.ingestion_log WHERE evidence_id = $1;

-- =============================================================================
-- TEMPORAL QUERIES (Chain of Custody)
-- =============================================================================

-- Query: "Where was this evidence stored on March 1?"
-- SELECT * FROM evidence_master_index
-- FOR SYSTEM_TIME AS OF '2026-03-01 00:00:00'
-- WHERE source_hash = 'abc123...';

-- Query: "Show me the full history of this evidence"
-- SELECT * FROM evidence_master_index_history
-- WHERE evidence_id = '...';
```

## Phase 6: Update GraphQL Resolvers

With FDW architecture, GraphQL resolvers become simpler:

**Before (complex):**
```typescript
// Multiple database connections
const mysqlResult = await mysqlDb.select()...
const pgResult = await pgDb.select()...
const neo4jResult = await neo4j.run(...)...
// Manual merge in JavaScript
```

**After (simple):**
```typescript
// Single PostgreSQL connection
const result = await pgDb.execute(sql`
  SELECT e.evidence_id, e.source_hash, m.text, n.entity_name
  FROM evidence_master_index e
  JOIN duckdb_tier1.ingestion_log i ON i.evidence_id = e.evidence_id
  JOIN messaging_messages m ON m.file_hash = e.source_hash
  JOIN neo4j_knowledge_graph.entities n ON n.evidence_id = e.evidence_id
  WHERE e.source_hash = ${hash}
`);
```

## Phase 7: Update Semantica Pipeline

Semantica can now query all tiers from PostgreSQL:

```python
# Semantica gets richer context
query = """
SELECT 
    n.entity_name,
    n.entity_type,
    m.text,
    m.timestamp,
    e.storage_path
FROM neo4j_knowledge_graph.entities n
JOIN duckdb_tier1.normalized_messages m ON m.evidence_id = n.evidence_id
JOIN evidence_master_index e ON e.evidence_id = n.evidence_id
WHERE n.entity_name = $entity_name
ORDER BY m.timestamp
"""
```
