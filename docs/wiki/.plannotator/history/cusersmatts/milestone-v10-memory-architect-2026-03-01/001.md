# Milestone v1.0: Memory Architecture & Deployment

**Core Value:** Raw messaging exports → temporally-aware, forensically-hashed evidence with bidirectional LLM/Portal/API access
**Architecture:** Hybrid DB (PostgreSQL+MySQL) + DuckDB + LanceDB + Dual Neo4j

---

## Part 1: The Requirements

### 1. Database Architecture (Hybrid)
- [ ] **DB-01**: The system must simultaneously initialize and maintain connections to both MySQL (App Control Plane) and PostgreSQL + PostGIS/TimescaleDB (Evidence Data Plane).
- [ ] **DB-02**: The 11,000-line legacy Drizzle Postgres schemas must compile cleanly and map exclusively to the PG evidence database without colliding with the MySQL app state.

### 2. Async Memory Service (The Zep-Clone)
- [ ] **MEM-01**: The system must run a dedicated Python FastAPI service (`mcp-memory-service`) alongside Node.js to handle heavy semantic/graph processing asynchronously.
- [ ] **MEM-02**: The Python service must integrate **Semantica** as the primary semantic orchestrator, utilizing `AgentContext` and `record_decision()` to log behavioral flags with W3C PROV-O provenance.
- [ ] **MEM-03**: The Python service must integrate **Graphiti** to automatically build Episodic memory and Temporal Edges (`valid_from`/`valid_to`) from extracted entities.
- [ ] **MEM-04**: Every Node, Edge, and Decision created by Semantica/Graphiti must retain unbreakable UUIDv7 links back to the original text chunk and Document hash.

### 3. Large File Ingestion (4GB Pipeline)
- [ ] **ING-01**: A background watcher daemon must monitor the local block storage for completed file transfers (via Rclone).
- [ ] **ING-02**: The ingestion pipeline must use stream-based processing to calculate SHA-256 hashes for massive files without loading them into RAM.
- [ ] **ING-03**: DuckDB must serve as the Tier 1 "Holding Tank" to chunk the massive files and assign UUIDv7s before handing them off to the async memory service.

### 4. Infrastructure & Deployment
- [ ] **INF-01**: The platform must be deployable via a unified `docker-compose` file designed for Coolify.
- [ ] **INF-02**: The deployment must include a Tailscale sidecar running in host network mode to securely bridge the VPS network with local admin tools.
- [ ] **INF-03**: The architecture must explicitly support mounting a 50GB Block Storage volume for the Cloudflare R2 / Rclone evidence drop.

## Part 2: The Execution Roadmap

### Phase 1: The Hybrid Foundation
**Goal:** Successfully compile the application and simultaneously initialize MySQL (App Layer) and PostgreSQL (Evidence Layer).
**Success Criteria:**
1. `tsc --noEmit` exits 0 with zero TypeScript errors.
2. `server/core/db.ts` successfully exposes `getAppDb()` (MySQL) and `getEvidenceDb()` (Postgres/DuckDB).
3. The legacy 11,000-line `production-message-schemas.ts` compiles natively against the PostgreSQL engine without stubs.
4. `docker-compose.coolify.yml` boots both MySQL and PostgreSQL (with PostGIS/TimescaleDB) side-by-side.

### Phase 2: Ingestion & Chain of Custody
*(Note: Bulk of this phase was drafted during Sprint 1, awaiting Phase 1 integration)*
**Goal:** Ingest massive 4GB evidence files synchronously using stream processing to preserve RAM and log immutable SHA-256 hashes to DuckDB.
**Success Criteria:**
1. Node.js Streams parse 4GB XML files line-by-line.
2. `hashFileStream` calculates SHA-256 in 64KB increments without loading the file into memory.
3. Every chunk receives a UUIDv7 and inherently links back to the original file's hash in DuckDB.
4. A background daemon (`watcher.ts`) monitors the block storage for completed file transfers.

### Phase 3: Infrastructure Deployment
**Goal:** Deploy the complete 5-Tier architecture to a 3-VPS environment managed by Coolify.
**Success Criteria:**
1. Coolify successfully reads the `docker-compose.coolify.yml` file from GitHub.
2. Traefik automatically routes `app.mitechconsult.com` to the UI and `api.mitechconsult.com` to the headless MCP backend.
3. The 50GB Block Storage volume is correctly mounted into the Node.js container for evidence ingestion.
4. The Tailscale sidecar allows direct admin access to the `10.10.x.x` VPC.

### Phase 4: Zep-Clone Memory Service (FastAPI)
**Goal:** Extract Graphiti and Semantica out of Node.js and into a dedicated Python asynchronous memory service.
**Success Criteria:**
1. Node.js successfully posts text chunks to the `mcp-memory-service` via REST/FastAPI.
2. Semantica (`AgentContext`) receives the chunks, runs NER (GLiNER2), and writes PROV-O validated facts to Neo4j DB #2.
3. Graphiti receives the entities, tracks valid timestamps, and writes episodic nodes to Neo4j DB #1.
4. Semantica successfully executes `record_decision()` when DARVO regex flags are triggered, creating auditable decision nodes in the graph.
