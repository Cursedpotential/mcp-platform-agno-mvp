# Modular Document AI & NER Augmentation Plan

## Core Philosophy: 100% Modular & Interchangeable
Based on your feedback, this architecture is designed as a **plug-and-play pipeline**. No hardcoded dependencies. Every capability (parsing, OCR, NER) sits behind an interface. We can swap, stack, or conditionally route to different modules based on the document type, the required accuracy, or if a weak point is discovered.

---

## Layer 1: Document Parsing & OCR Pipeline (The "Readers")
*Goal: Turn raw files (PDFs, DOCX, images, screenshots) into clean, structured Markdown/JSON chunks.*

### Primary Modules (Local / Open Source)
1. **Docling (IBM)** — Primary parser for complex PDFs, PPTX, DOCX. Excellent table and layout understanding.
2. **DocStrange (Nanonets)** — Alternative local parser for tricky layouts and forms.
3. **Unstructured.io** — The industry-standard fallback for weird file types (HTML, EML, EPUB). Highly modular internally.

### Advanced / Cloud Modules (Opt-in / Fallbacks)
4. **Amazon Textract** — *Specific Task Routing:* Hardcoded route for **Screenshots of text messages** and raw images, where it outperforms standard PDF parsers.
5. **LlamaParse (LlamaIndex)** — *Specific Task Routing:* Cloud fallback for extremely messy or complex PDFs where local models struggle to preserve reading order.

---

## Layer 2: Entity Extraction Pipeline (The "Extractors")
*Goal: Extract people, dates, events, emotions, and locations from the clean text.*

### Primary Modules (Local / $0 Cost)
1. **GLiNER2 (Fastino)** — *Core NER.* Handles semantic entities (person, communication, event, location, legal_proceeding). Zero-shot, highly accurate, runs on CPU.
2. **Recognizers-Text (Microsoft)** — *Structured Data.* Handles exact dates ("next Tuesday", "March 15"), currency, and phone numbers natively in Node.js.

### Advanced / Cloud Modules (Opt-in / Fallbacks)
3. **IBM Watson NLU** — *Advanced Fallback.* Used for complex semantic roles (Subject-Action-Object) and **Emotion Analysis** (scoring anger, fear, sadness in communications).
4. **Google Cloud NL API + Maps API** — *Specific Task Routing:* Whenever an entity is tagged as a `Location` or `Address`, route it to Google NL for structured parsing (street, city, zip), then validate it against the **Google Maps API** for exact geocoding and real-world validation.

---

## Layer 3: Validation & Provenance (The "Truth Filter")
*Goal: Ensure no garbage enters the graph.*

1. **Semantica (Hawksight-AI)** — *Always On.*
   - Takes the output from *all* Layer 2 modules.
   - Handles W3C PROV-O provenance (e.g., "Address X was extracted by Google NL from Document Y").
   - Detects conflicts (e.g., GLiNER2 found a person, but it conflicts with existing graph data).
   - Writes validated `semantic_facts` to Neo4j.
2. **Human-in-the-Loop (Rule #8)** — *Always On.*
   - If Semantica detects a conflict, or if module confidence scores are too low, the pipeline pauses and surfaces the UI for manual human resolution.

---

## Pipeline Routing Logic (Example Configuration)

Because everything is modular, the pipeline router decides which modules fire based on the input:

```typescript
// Pseudo-code demonstrating the modular routing

async function processEvidence(file) {
  let textChunks;
  
  // 1. DYNAMIC PARSER ROUTING
  if (file.type === 'image/screenshot') {
     // Textract is best for raw message screenshots
     textChunks = await TextractModule.parse(file);
  } else if (file.complexity === 'extreme') {
     textChunks = await LlamaParseModule.parse(file);
  } else {
     // Default local stack
     textChunks = await DoclingModule.parse(file) || await UnstructuredModule.parse(file);
  }

  // 2. PARALLEL NER EXTRACTION
  const entities = [];
  
  // Always run local stack
  entities.push(...await GLiNER2Module.extract(textChunks));
  entities.push(...await RecognizersTextModule.extract(textChunks));
  
  // Conditionally run advanced cloud modules
  if (requiresEmotionAnalysis(textChunks)) {
      entities.push(...await IBMWatsonModule.extract(textChunks));
  }

  // 3. SPECIALIZED ENRICHMENT (Google Address Parsing)
  for (let entity of entities) {
      if (entity.type === 'ADDRESS' || entity.type === 'LOCATION') {
          const structuredAddress = await GoogleNLModule.parseAddress(entity.rawText);
          entity.validatedData = await GoogleMapsModule.validate(structuredAddress);
      }
  }

  // 4. SEMANTICA VALIDATION
  const validatedFacts = await SemanticaModule.processAndDetectConflicts(entities);
  
  return validatedFacts;
}
```

## Why this approach wins:
1. **Future-Proof:** If a better parser comes out next month, we just write a new `ParserModule` wrapper and drop it in.
2. **Cost-Optimized:** 90% of documents process locally for free (Docling + GLiNER2 + Semantica). 
3. **Specialized:** Textract only fires when it's a screenshot. Google NL only fires when we find an address. IBM Watson only fires when we need emotion parsing.
4. **Verified Locations:** Google Address Parsing + Google Maps API ensures physical locations in custody disputes are real, mapped, and formatted consistently.
