### Success Criteria Detail

**Phase 1: Compilation Foundation**
*Goal: The entire TypeScript codebase compiles without errors — all plugins fixed properly, not patched to pass*

1. `npx tsc --noEmit` exits with code 0 (currently 292 errors across 30 files)
2. All 37 tool plugins in the registry load without import errors
3. Archive files (`server/mcp/storage/archive/`) excluded from TypeScript compilation via tsconfig
4. No dead Graphiti/Chroma/Neo4j imports remain in any active source file

**Phase 2: Database Architecture**
*Goal: All 5 database tiers initialize simultaneously and accept evidence*

1. App boots and logs successful connections to MySQL, PostgreSQL, DuckDB, LanceDB, and Neo4j
2. PostgreSQL evidence schema has `messages`, `conversations`, and `files` tables with full-text search indexes
3. SHA-256 hash is computed at first touch (before any transformation)
4. The same evidence hash appears in DuckDB ingestion_log, LanceDB metadata, and PostgreSQL message records

**Phase 3: Ingestion End-to-End**
*Goal: Raw messaging exports flow through the full pipeline into all database tiers*

1. User drops a messaging export into the watched folder → it appears in DuckDB, LanceDB, and PostgreSQL without manual intervention
2. Each message chunk has a UUIDv7 linked to the parent file's SHA-256 hash
3. TrinityRouter fires HTTP POST to the Python memory service URL for async graph processing (fire-and-forget, 202 pattern)

**Phase 4: Python Memory Service (Scaffolding)**
*Goal: A standalone Python FastAPI service runs and accepts evidence chunks from Node.js*

1. `mcp-memory-service` starts via `uvicorn` and responds to `GET /health`
2. Node.js TrinityRouter POSTs to `POST /memory/ingest` and receives 202 Accepted immediately
3. Service logs received evidence chunks with their UUIDv7, source_hash, and document_hash

**Phase 5: Semantica Knowledge Graph**
*Goal: Ingested evidence automatically builds a temporal knowledge graph in Neo4j with full provenance*

1. Semantica extracts entities from text chunks and creates validated nodes in Neo4j
2. Every Neo4j node contains `chunk_id` (UUIDv7) and `document_id` properties linking back to DuckDB
3. W3C PROV-O provenance chains are attached to every node created by Semantica
4. `query_at_time()` returns entity state as of a specific date

**Phase 6: Pass 1 Enrichment**
*Goal: Every ingested message gets blind NLP classification within a 24-hour context window*

1. Messages classified for sentiment, intent, and entities using local CPU tools (303 regex patterns, GLiNER2, Recognizers-Text)
2. 768-dimensional embeddings generated and stored in LanceDB
3. Classification results are WORM (Write Once, Read Many) — never modified after creation
4. Results locked with SHA-256 reference in DuckDB

**Phase 7: Infrastructure Deployment**
*Goal: Complete 5-Tier platform deployed to Hetzner VPS accessible via Tailscale*

1. `docker-compose.coolify.yml` boots all containers: Node.js, Python Memory Service, MySQL, PostgreSQL, Neo4j, Tailscale sidecar
2. 50GB block storage volume correctly mounted for evidence ingestion via Rclone
3. All 5 tier connection strings configurable via environment variables
4. Platform accessible via Tailscale VPC at `10.10.x.x`

**Phase 8: Pass 2 Enrichment (Hindsight)**
*Goal: User-triggered longitudinal analysis reveals behavioral patterns invisible in real-time*

1. User can trigger Pass 2 analysis on any conversation or time range
2. Pass 2 uses full longitudinal context (not limited to 24-hour window like Pass 1)
3. Gaslighting detection compares Pass 1 sentiment ("how it felt at the time") against Pass 2 longitudinal patterns ("what actually happened") and creates CONTRADICTS edges in Neo4j
4. Pass 2 creates annotations that reference but never modify Pass 1 results

### Key Design Decisions

1. **Phase 1 is compilation ONLY** — no feature work, just make it build. This is the foundation everything else depends on. 292 errors across 30 files, every plugin fixed properly (not Gemini-style patching).

2. **Infrastructure is Phase 7 (late)** — you can develop and test Phases 2-6 locally. Infrastructure deployment needs stable code, not the other way around.

3. **Pass 2 is last** — it depends on Pass 1 data existing AND the knowledge graph being populated. Can't do hindsight analysis without history.

4. **Python service splits into two phases** (4 + 5) — scaffolding first (get the HTTP contract working), Semantica integration second (complex cookbook implementation).
