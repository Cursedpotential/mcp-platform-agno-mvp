# Plan: Comprehensive Input Validation Enhancement

## Context
The MCP Tool Platform's `validateInputMetadata` function (coordinator.ts:104-114) has multiple blocking issues that prevent evidence processing:
- No sanitization before validation
- Generic error messages without field context
- No support for common date formats
- Case-sensitive enum matching
- No handling for edge cases (Unicode, whitespace, SQL injection)

User wants a comprehensive single-phase implementation covering all three required fields: `device_id`, `device_owner`, `extraction_date`.

## Files to Create

**New files:**
- `server/mcp/ingest/validation.ts` - New validation utilities module
- `server/mcp/ingest/validation.test.ts` - Unit tests for validation
- `server/mcp/ingest/types.ts` - Shared validation types
- `client/src/components/UploadForm.tsx` - Client-side validation UI (concept - file may not exist)

**Files to modify:**
- `server/mcp/ingest/coordinator.ts` - Replace validation logic with new utilities

### Phase 3: Add Error Response Types

**File:** `server/mcp/ingest/types.ts`

```typescript
export interface ValidationError {
  field: 'device_id' | 'device_owner' | 'extraction_date' | 'extraction_method';
  errorType: 'required' | 'format' | 'sanitization_failed' | 'unknown';
  message: string;
  details?: any;
}

export interface ValidationResult {
  valid: boolean;
  sanitized: Record<string, any>;
  errors: ValidationError[];
}

export function buildValidationError(
  field: string,
  errorType: ValidationError['errorType'],
  message: string,
  details?: any
): ValidationError {
  return { field, errorType, message, details };
}
```
