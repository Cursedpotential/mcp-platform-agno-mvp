# docs/schema — canonical, generated, always current

> _Byline: Claude Code · Fable 5 · 2026-08-25 (owner directive same day: "these become canonical and a hard requirement; they stay up to date with everything else and they always exist")_

## What lives here

| File | What it is | Generated by |
|---|---|---|
| `catalog.json` | Every relation in live `ai` (+ names/rows for `ai_test_ingest`, `traceiq`): columns, types, defaults, comments, constraints, inbound FKs, indexes, view definitions. | `scripts/schema_report/catalog.py` |
| `ai-schema-reckoning.html` | Every relation with a keep / drop / review verdict and a Now / Why / After strip. | `scripts/schema_report/build_reckoning.py` |
| `three-message-shapes.html` | End-to-end data-flow chart + the three message shapes (June D2/D7, ADR-0059/0053, merge) with every column. | `scripts/schema_report/build_shapes.py` |

## The rule

- **These pages are the schema's public face.** A table that is not in `catalog.json` does not exist as far as the platform is concerned; a table in `catalog.json` with no verdict is a defect.
- **Never hand-edit the HTML or JSON.** Change the live schema (via a numbered migration under `sql/`) or the generator, then regenerate.
- **Regenerate in the same change as any migration.** `uv run python scripts/schema_report/catalog.py docs/schema/catalog.json && uv run python scripts/schema_report/build_reckoning.py docs/schema docs/schema/ai-schema-reckoning.html && uv run python scripts/schema_report/build_shapes.py docs/schema docs/schema/three-message-shapes.html`
- **Freshness is enforced live**, not by convention: `tests/test_schema_docs_current.py` (marker `integration`) re-reads `pg_catalog` on `100.91.190.107:5432/ai` and fails when the live relation set or any column set differs from `catalog.json`. A red run means either the DB moved without a regen, or someone created a table outside `sql/`.

## Why it exists

Between 2026-07-03 and 2026-08-24 the live `ai` database grew from the owner-approved 93-table design to 241 relations across three overlapping schemas, with `sql/bootstrap/schema_baseline.sql` re-blessing every stray on each capture. No declarative "these tables and only these" existed. This directory is that declaration, and the test is the balancing loop the system was missing.
