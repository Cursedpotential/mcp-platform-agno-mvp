# ADR-0007: Incorporate n8n + Cloudflare R2; R2 = blob/object landing zone
- Status: Accepted
- Date: 2026-06-01

## Context
The existing stack already runs an **n8n** automation service and a **Cloudflare R2** volume (S3-compatible)
via rclone. The handoff (§17) calls for blob/object storage as the raw-evidence landing zone that
Semantica reads natively (S3/Azure/GCS). The owner confirmed both are in scope.

## Decision
A single `compose.yaml` carries `postgres` (PG18), `agno-app` (built image), **`n8n`**, and the
**`r2_shared_cloud`** rclone volume. **R2 is adopted as the §17 blob/object landing zone** (raw evidence
+ knowledge archives; Agno/Semantica read S3-compatible storage natively). n8n stays as the automation
layer on the shared Postgres (its own DB/schema, isolated from `evidence`/`analysis`) and may call the
AgentOS REST endpoints.

## Consequences
- R2 bucket/prefix layout needs a provenance-friendly convention (raw vs derived vs knowledge).
- If n8n drives the platform, consider `enable_mcp_server=True` so it can call agents as MCP tools.
- n8n tables must never live under the evidence/analysis schemas.

## Alternatives considered
- Separate compose files / dropping n8n — rejected: owner wants them integrated.
- DuckDB/local staging for raw evidence — rejected (see ADR-0003).
