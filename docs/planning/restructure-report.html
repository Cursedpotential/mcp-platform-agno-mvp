5 · Why the repack is a runbook, not a merge

Lane C reported that main now auto-deploys the exec tier and Dockerfiles COPY configs at build time. The repack changes the uvicorn entrypoint and every COPY path — so a lagging or partial change means a failed production redeploy. It also can't sit as a branch: Lane B is editing .py and Lane C is editing docker/, so an open repack branch rots fast. Best practice = one all-or-nothing window with a local docker build proof before merge.
