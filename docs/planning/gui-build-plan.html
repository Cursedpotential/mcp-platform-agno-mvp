GUI Build Plan — G1 through G6

Scope: GUI units only · Part-2 behavioral engines excluded · security pre-work already handled · spec's suggested order followed.
Source: gui-integration-spec.md + port-backlog.md. Working draft — argue with it.

Build order

G1→ G4→ VPS window→ G2→ G3→ G5→ G6
Why this order
  • G1 & G4 go first — both are fully offline and unlock the most. G1 is the shell everything else mounts into; G4 is the agent-facing tool surface that needs no UI.
  • G2 & G3 batch together — they're the only VPS-gated units, so they fit into a single server window.
  • G5 & G6 come last — buildable offline against fixtures, but they need G1's shell to exist first.

G4tool-finder meta-MCP serverOffline

Done when

  • Large outputs return a content-addressed ref instead of the payload.
Decided · Q7 get_ref store Locked: local SQLite cache on the tool-finder host — SHA-256 keyed, WAL mode, TTL-swept. Fast local paging; not R2 (slow, full buckets), not Redis/Dragonfly. Big tool results are written to the local cache and handed back as a short ref id; get_ref pages them out by byte offset. Durable artifacts (court exports, exhibits) still go to custody / R2 on a deliberate write — separate lane.

Decisions — all locked

  • Q1 · Shell placement — ui/ in-repo.
  • Q2 · Auth — single proxy JWT for everything.
  • Q5 · CF version — stay on 1.0.3; upgrade the live 0.8.0 box to match before G3.
  • Q6 · MVP page — tool catalog first, evidence browser second.
  • Q7 · get_ref store — local SQLite cache on the tool-finder host (SHA-keyed, WAL, TTL-swept); R2 only for deliberate durable artifacts.
  • Q3 & Q4 — AgentOS UI framed as-is first; Kasm + OpenCode each get a nav entry. Both inside G2.

Non-goals — held firm

  • No rebuilding chat, agent control, or tool management from scratch.
  • No porting the donor's tRPC / Node data layer — bind REST/OpenAPI + AG-UI.
  • No public internet exposure in G1–G6 — tailnet + proxy auth only.
  • No per-parser UI — bind to registry ids / capabilities only.
  • No workflow-designer UI — that stays a separate owner brainstorm.
